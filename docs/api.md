## 1. Общие правила

### 1.1. Формат

- Базовый адрес: `http://localhost:8080/api`.
- Тела запросов и ответов — JSON в кодировке UTF-8, заголовок `Content-Type: application/json`.
- Имена полей — `snake_case`, совпадают с именами столбцов БД.
- Идентификаторы — целые числа.
- Даты и время — строки по RFC 3339 с часовым поясом, например `2026-11-12T10:15:00+03:00`.
- Денежные значения — числа с двумя знаками после запятой (`8.90`, `331.50`), округление на сервере. Расчёты на Go ведутся в целых копейках (или decimal), `float64` для денег не используется.
- Пустое значение — `null`.
- Пароль и его хеш в ответах API не передаются никогда.

### 1.2. Авторизация

Защищённые эндпоинты требуют заголовок:

```
Authorization: Bearer <JWT>
```

JWT подписывается алгоритмом HS256, секрет берётся из переменной окружения `JWT_SECRET`. Claims токена:

| Claim | Значение |
|---|---|
| `user_id` | идентификатор пользователя |
| `role` | `client`, `manager` или `admin` |
| `iat`, `exp` | время выпуска и окончания, срок жизни 30 минут |

После истечения срока сервер отвечает `401`, и интерфейс отправляет пользователя на страницу входа.

При каждом защищённом запросе middleware загружает пользователя по `user_id` из БД. Если пользователь удалён, сервер отвечает `401 unauthorized`. Роль для проверки прав берётся из БД, а не из токена, поэтому смена роли администратором действует сразу, а claim `role` служит только подсказкой для интерфейса. Токены, выданные до смены пароля, остаются действительными до истечения срока (30 минут), отзыв токенов вынесен в направления развития.

### 1.3. Списки, поиск и сортировка

Эндпоинты-списки возвращают объект:

```json
{ "items": [ ... ], "total": 18 }
```

Общие параметры запроса (в зависимости от эндпоинта):

| Параметр | Назначение |
|---|---|
| `q` | поиск по подстроке без учёта регистра; по каким полям — указано у эндпоинта |
| `sort` | поле сортировки из списка допустимых для эндпоинта |
| `order` | `asc` (по умолчанию) или `desc` |
| фильтры | например `status`, `tariff_id`, `car_id` |

Недопустимое значение `sort` или `order` — ошибка `400 validation_error`. Допустимые поля сортировки заданы белым списком в коде и подставляются в SQL только из него, значения параметров всегда передаются через плейсхолдеры (защита от SQL-инъекций).

### 1.4. Формат ошибок

Все ошибки возвращаются в едином виде:

```json
{
  "error": {
    "code": "validation_error",
    "message": "Некорректные данные запроса",
    "details": { "fuel_level": "должно быть от 0 до 100" }
  }
}
```

`code` — стабильный машинный код, `message` — текст для показа пользователю на русском языке, `details` — необязательные подробности (для ошибок валидации — поле и причина).

HTTP-коды:

| Код | Когда |
|---|---|
| `200 OK` | успешное чтение или изменение |
| `201 Created` | объект создан |
| `204 No Content` | успешное удаление или действие без тела ответа |
| `400 Bad Request` | некорректные данные |
| `401 Unauthorized` | токена нет, он неверный или просрочен; неверный логин или пароль |
| `403 Forbidden` | роли недостаточно или чужой ресурс |
| `404 Not Found` | объект не найден |
| `405 Method Not Allowed` | путь существует, но метод другой; допустимые методы — в заголовке `Allow` |
| `409 Conflict` | конфликт данных или состояния |
| `429 Too Many Requests` | слишком много неудачных попыток входа; время ожидания — в заголовке `Retry-After` (секунды) |
| `500 Internal Server Error` | непредвиденная ошибка сервера (подробности только в логе) |

Коды ошибок (`error.code`):

| Код | HTTP | Значение |
|---|---|---|
| `validation_error` | 400 | не прошла проверка полей |
| `wrong_password` | 400 | неверный текущий пароль при смене пароля |
| `unauthorized` | 401 | нет токена, токен неверный или просрочен |
| `invalid_credentials` | 401 | неверный email или пароль (текст один и тот же в обоих случаях) |
| `forbidden` | 403 | недостаточно прав |
| `license_required` | 403 | у клиента не заполнено водительское удостоверение |
| `cannot_change_own_role` | 403 | администратор пытается изменить свою роль |
| `cannot_delete_self` | 403 | администратор пытается удалить себя |
| `not_found` | 404 | объект не найден |
| `email_taken` | 409 | email уже занят |
| `license_taken` | 409 | водительское удостоверение уже зарегистрировано |
| `plate_taken` | 409 | гос. номер уже есть в системе |
| `name_taken` | 409 | тариф с таким названием уже есть |
| `car_unavailable` | 409 | автомобиль нельзя забронировать (не `available` или его уже забронировали) |
| `user_has_active_rental` | 409 | у пользователя есть бронирование или активная аренда |
| `invalid_status_transition` | 409 | недопустимая смена статуса |
| `has_related_records` | 409 | нельзя удалить объект, на который ссылаются другие записи |
| `method_not_allowed` | 405 | метод не поддерживается для этого адреса |
| `booking_expired` | 409 | срок бронирования истёк: оно отменено, ожидание списано |
| `conflict` | 409 | нарушена уникальность, для которой нет отдельного кода |
| `too_many_attempts` | 429 | вход временно заблокирован после серии неудачных попыток |
| `internal_error` | 500 | внутренняя ошибка |

Соответствие ошибок PostgreSQL: `23505` (нарушение уникальности) → `409` с соответствующим кодом (для индексов аренд код определяется по имени: `uq_rentals_one_active_per_car` → `car_unavailable`, `uq_rentals_one_active_per_user` → `user_has_active_rental`; неизвестное ограничение → `409 conflict`), `23503` при удалении (внешний ключ) → `409 has_related_records`, `23514` (нарушение `CHECK`) → `400 validation_error` (до этого запрос должен был отсеяться проверкой в сервисе).

## 2. Статусы и переходы

### 2.1. Аренда (`rentals.status`)

| Из | В | Действие | Кто |
|---|---|---|---|
| — | `booked` | бронирование `POST /api/rentals` | клиент |
| `booked` | `active` | старт `POST /api/rentals/{id}/start` | клиент (владелец) |
| `booked` | `cancelled` | отмена `POST /api/rentals/{id}/cancel` | клиент (владелец), менеджер, админ |
| `booked` | `cancelled` | истечение срока бронирования (20 минут) | сервер автоматически |
| `active` | `completed` | завершение `POST /api/rentals/{id}/finish` | клиент (владелец) |

`completed` и `cancelled` — конечные статусы. Любой другой переход — `409 invalid_status_transition`.

**Срок бронирования — 20 минут** (`expires_at` в объекте аренды). Просроченные бронирования сервер отменяет фоновой задачей (раз в 15 секунд), а также при попытке начать поездку, отменить бронирование или забронировать машину. У отменённой аренды `ended_at` — момент отмены (для истёкшей — конец срока), `total_cost` — списанное ожидание.

### 2.2. Автомобиль (`cars.status`)

Статус меняется автоматически вместе с арендой в одной транзакции:

| Событие | Статус автомобиля |
|---|---|
| бронирование | `available` → `booked` |
| старт поездки | `booked` → `in_use` |
| завершение поездки | `in_use` → `available` |
| отмена бронирования | `booked` → `available` |

Вручную менеджер и админ могут менять только так (`PATCH /api/cars/{id}/status`):

| Из | В |
|---|---|
| `available` | `maintenance`, `decommissioned` |
| `maintenance` | `available`, `decommissioned` |
| `decommissioned` | `available` |

Автомобиль в статусе `booked` или `in_use` вручную менять нельзя — `409 invalid_status_transition`.

### 2.3. Расчёт стоимости

При завершении аренды:

```
минуты_поездки   = max(1, округление вверх (ended_at − started_at) до целой минуты)
минуты_ожидания  = округление вверх (started_at − booked_at) до целой минуты
total_cost       = round(price_per_min × минуты_поездки + waiting_per_min × минуты_ожидания, 2)
```

При отмене бронирования (поездка не начиналась):

```
минуты_ожидания  = min(20, округление вверх (момент_отмены − booked_at) до целой минуты)
total_cost       = waiting_per_min × минуты_ожидания   — отмена клиентом или истечение срока
total_cost       = 0                                    — отмена менеджером или администратором
```

Истёкшее бронирование стоит ровно 20 минут ожидания. Отмена сотрудником бесплатна для клиента: обычно её причина — сам автомобиль.

Цены берутся из самой аренды (`price_per_min`, `waiting_per_min`), а не из тарифа, поэтому изменение тарифа старые аренды не затрагивает.

## 4. Служебные

### `GET /api/health`

Доступ: любой (токен не нужен). Технический эндпоинт для проверки, что сервер запущен и видит БД. В матрице доступа не учитывается.

**200 OK**
```json
{ "status": "ok", "database": "ok" }
```

**503 Service Unavailable** — БД недоступна:
```json
{ "status": "degraded", "database": "unavailable" }
```

### `GET /about`

HTML-страница «Об авторе», доступна всем без входа. Своих данных из API не загружает; как и любая страница интерфейса, при наличии токена запрашивает `GET /api/me`, чтобы показать меню по роли.

## 5. Аутентификация и профиль

### `POST /api/auth/register`

Доступ: гость. Создаёт клиента (роль всегда `client`, поле `role` в запросе игнорируется).

**Запрос**
```json
{
  "email": "ivan.petrov@example.com",
  "password": "Client123!",
  "full_name": "Петров Иван Сергеевич",
  "driver_license": "7712 345678"
}
```

Все поля обязательны (правила — в разделе 12). Водительское удостоверение сохраняется в нормализованном виде `NNNN NNNNNN`.

**201 Created**
```json
{
  "id": 4,
  "email": "ivan.petrov@example.com",
  "full_name": "Петров Иван Сергеевич",
  "driver_license": "7712 345678",
  "role": "client",
  "created_at": "2026-11-12T10:00:00+03:00"
}
```

**Ошибки:** `400 validation_error`, `409 email_taken`, `409 license_taken`.

### `POST /api/auth/login`

Доступ: гость.

**Запрос**
```json
{ "email": "ivan.petrov@example.com", "password": "Client123!" }
```

**200 OK**
```json
{
  "token": "<JWT>",
  "token_type": "Bearer",
  "expires_in": 1800,
  "user": {
    "id": 4,
    "email": "ivan.petrov@example.com",
    "full_name": "Петров Иван Сергеевич",
    "driver_license": "7712 345678",
    "role": "client",
    "created_at": "2026-10-01T09:00:00+03:00"
  }
}
```

**Ошибки:** `400 validation_error` (пустой email или пароль), `401 invalid_credentials` («Неверный email или пароль» — одинаково для неверного email и неверного пароля), `429 too_many_attempts`.

**Защита от подбора пароля.** Неудачные попытки считаются отдельно по email и по IP-адресу за последние 15 минут. После 5 неудач для одного email или 20 неудач с одного IP вход блокируется (даже с верным паролем) до истечения окна: ответ `429 too_many_attempts` с заголовком `Retry-After`. Успешный вход сбрасывает счётчик email.

### `GET /api/me`

Доступ: К, М, А. Возвращает профиль текущего пользователя в формате объекта `user` (как в ответе на регистрацию). Только чтение: ФИО, email и водительское удостоверение сам пользователь менять не может.

### `PUT /api/me/password`

Доступ: К, М, А.

**Запрос**
```json
{ "current_password": "Client123!", "new_password": "NewPass456!" }
```

**204 No Content.** Обновляется только `password_hash`.

**Ошибки:** `400 validation_error` (слабый новый пароль), `400 wrong_password`.

## 6. Каталог и тарифы (чтение)

Объект автомобиля (`car`):

```json
{
  "id": 1,
  "brand_model": "Kia Rio",
  "plate_number": "А101АА777",
  "fuel_level": 78,
  "latitude": 55.7558,
  "longitude": 37.6173,
  "status": "available",
  "tariff": { "id": 1, "name": "Эконом", "price_per_min": 8.90, "waiting_per_min": 2.00 }
}
```

Объект тарифа (`tariff`): `{ "id": 1, "name": "Эконом", "price_per_min": 8.90, "waiting_per_min": 2.00 }`.

### `GET /api/cars`

Доступ: К, М, А. Список для таблицы каталога и для карты.

| Параметр | Описание |
|---|---|
| `q` | поиск по `brand_model` и `plate_number` |
| `status` | фильтр по статусу; для клиента игнорируется (всегда только `available`) |
| `tariff_id` | фильтр по тарифу |
| `sort` | `id`, `brand_model`, `plate_number`, `fuel_level`, `price_per_min` |
| `order` | `asc` или `desc` |

**200 OK**
```json
{ "items": [ { "id": 1, "brand_model": "Kia Rio", "...": "..." } ], "total": 12 }
```

**Ошибки:** `400 validation_error` (неверные `sort`, `order`, `tariff_id`).

### `GET /api/cars/{id}`

Доступ: К, М, А. Клиент получает автомобиль, только если он `available` или входит в его текущую аренду (`booked`, `active`).

**200 OK** — объект `car`.

**Ошибки:** `404 not_found` (автомобиля нет; для клиента также если автомобиль ему недоступен).

### `GET /api/tariffs`

Доступ: К, М, А.

**200 OK**
```json
{ "items": [ { "id": 1, "name": "Эконом", "price_per_min": 8.90, "waiting_per_min": 2.00 } ], "total": 3 }
```

## 7. Управление автопарком и тарифами

Доступ ко всем эндпоинтам раздела: М, А.

### `POST /api/cars`

**Запрос**
```json
{
  "tariff_id": 1,
  "brand_model": "Kia Rio",
  "plate_number": "А101АА777",
  "fuel_level": 78,
  "latitude": 55.7558,
  "longitude": 37.6173
}
```

Начальный статус всегда `available`.

**201 Created** — объект `car`.

**Ошибки:** `400 validation_error` (в том числе несуществующий `tariff_id`), `409 plate_taken`.

### `PUT /api/cars/{id}`

Полная замена полей автомобиля (те же поля, что при создании). Статус этим запросом не меняется.

**200 OK** — объект `car`.

**Ошибки:** `400 validation_error`, `404 not_found`, `409 plate_taken`.

### `PATCH /api/cars/{id}/status`

**Запрос**
```json
{ "status": "maintenance" }
```

Допустимые значения: `available`, `maintenance`, `decommissioned`; переходы — по таблице 2.2.

**200 OK** — объект `car`.

**Ошибки:** `400 validation_error` (недопустимое значение), `404 not_found`, `409 invalid_status_transition` (в том числе когда автомобиль в статусе `booked` или `in_use`).

### `DELETE /api/cars/{id}`

**204 No Content.**

## 9. Аренды

Объект аренды (`rental`):

```json
{
  "id": 1,
  "user": { "id": 4, "full_name": "Петров Иван Сергеевич" },
  "car": { "id": 1, "brand_model": "Kia Rio", "plate_number": "А101АА777" },
  "tariff_id": 1,
  "booked_at": "2026-10-20T09:50:00+03:00",
  "expires_at": null,
  "started_at": "2026-10-20T10:00:00+03:00",
  "ended_at": "2026-10-20T10:35:00+03:00",
  "price_per_min": 8.90,
  "waiting_per_min": 2.00,
  "total_cost": 331.50,
  "status": "completed"
}
```

По статусам:

| Статус | `expires_at` | `started_at` | `ended_at` | `total_cost` |
|---|---|---|---|---|
| `booked` | когда бронирование истечёт | `null` | `null` | `null` |
| `active` | `null` | старт поездки | `null` | `null` |
| `completed` | `null` | старт поездки | конец поездки | стоимость поездки |
| `cancelled` | `null` | `null` | момент отмены | списанное ожидание (может быть `0`) |

### `POST /api/rentals`

Доступ: К.

**Запрос**
```json
{ "car_id": 7 }
```

В одной транзакции сервер проверяет условия, создаёт аренду со статусом `booked`, копирует в неё `tariff_id` и цены из автомобиля и переводит автомобиль в `booked`. Условия:

- у клиента заполнено водительское удостоверение;
- автомобиль в статусе `available` и не имеет активных бронирований (гарантируется блокировкой строки и частичным уникальным индексом в БД);
- у клиента нет другой аренды в статусах `booked` или `active` (гарантируется частичным уникальным индексом по `user_id`, поэтому два одновременных запроса одного клиента не создадут две аренды).

**201 Created** — объект `rental`.

**Ошибки:** `400 validation_error` (нет `car_id`), `403 license_required`, `404 not_found` (автомобиля нет), `409 car_unavailable`, `409 user_has_active_rental`.

### `POST /api/rentals/{id}/start`

Доступ: К (владелец аренды). Без тела запроса. Аренда `booked` → `active`, `started_at` ставится сервером, автомобиль → `in_use`.

Если срок бронирования истёк, поездка не начинается: бронирование отменяется со списанием 20 минут ожидания, отмена сохраняется, ответ — `409 booking_expired`.

**200 OK** — объект `rental`.

**Ошибки:** `403 forbidden` (чужая аренда), `404 not_found`, `409 invalid_status_transition` (аренда не в статусе `booked`), `409 booking_expired`.

### `POST /api/rentals/{id}/finish`

Доступ: К (владелец аренды). Аренда `active` → `completed`, `ended_at` ставится сервером, стоимость считается по правилу 2.3, автомобиль → `available`.

**Запрос** (поля необязательны; если переданы, обновляют место парковки автомобиля; `latitude` и `longitude` передаются только вместе)
```json
{ "latitude": 55.7601, "longitude": 37.6195 }
```

Уровень топлива клиент не передаёт: это состояние автомобиля, а не данные клиента, и самостоятельная отметка позволила бы скрыть пустой бак. Поле `fuel_level` в запросе игнорируется; уровень топлива меняет только менеджер (`PUT /api/cars/{id}`).

Место парковки клиент указывает сам: это допущение курсовой работы, у системы нет бортового оборудования, которое сообщало бы положение машины. В реальном сервисе координаты передаёт телематика автомобиля (см. `role_matrix.md`, раздел 6, п. 6).

**200 OK** — объект `rental` с заполненным `total_cost`.

**Ошибки:** `400 validation_error` (значения вне допустимых диапазонов или передана только одна из координат), `403 forbidden`, `404 not_found`, `409 invalid_status_transition` (аренда не в статусе `active`).

### `POST /api/rentals/{id}/cancel`

Доступ: К (владелец аренды), М, А (любое бронирование). Без тела запроса. Аренда `booked` → `cancelled`, `ended_at` — момент отмены, автомобиль → `available`.

Клиенту списывается ожидание по правилу 2.3; отмена менеджером или администратором бесплатна (`total_cost = 0`). Если срок бронирования уже истёк, оно отменяется как просроченное (20 минут ожидания).

**200 OK** — объект `rental` с заполненными `ended_at` и `total_cost`.

**Ошибки:** `403 forbidden` (клиент пытается отменить чужую аренду), `404 not_found`, `409 invalid_status_transition` (отменить можно только бронирование).

### `GET /api/rentals/my`

Доступ: К. Аренды текущего пользователя.

| Параметр | Описание |
|---|---|
| `status` | фильтр по статусу аренды |
| `sort` | `id`, `booked_at`, `total_cost`, `status` |
| `order` | `asc` или `desc` |

**200 OK** — `{ "items": [ <rental> ], "total": 3 }`.

### `GET /api/rentals`

Доступ: М, А. Все аренды.

| Параметр | Описание |
|---|---|
| `q` | поиск по ФИО пользователя и гос. номеру автомобиля (номер можно вводить латиницей и с пробелами, как в каталоге) |
| `status` | фильтр по статусу |
| `user_id`, `car_id` | фильтры по пользователю и автомобилю |
| `sort` | `id`, `booked_at`, `total_cost`, `status` |
| `order` | `asc` или `desc` |

**200 OK** — `{ "items": [ <rental> ], "total": 14 }`.

### `GET /api/rentals/{id}`

Доступ: К (только своя), М, А.

**200 OK** — объект `rental`.

**Ошибки:** `403 forbidden` (клиент запрашивает чужую аренду), `404 not_found`.

Редактировать и удалять аренды вручную нельзя: статус меняется только через `start`, `finish` и `cancel`, история защищена.

## 10. Пользователи

Доступ ко всем эндпоинтам раздела: А. Объект пользователя (`user`):

```json
{
  "id": 4,
  "email": "ivan.petrov@example.com",
  "full_name": "Петров Иван Сергеевич",
  "driver_license": "7712 345678",
  "role": "client",
  "created_at": "2026-10-01T09:00:00+03:00"
}
```

### `GET /api/users`

| Параметр | Описание |
|---|---|
| `q` | поиск по `email` и `full_name` |
| `role` | фильтр по роли |
| `sort` | `id`, `email`, `full_name`, `created_at` |
| `order` | `asc` или `desc` |

**200 OK** — `{ "items": [ <user> ], "total": 9 }`.

### `PATCH /api/users/{id}/role`

**Запрос**
```json
{ "role": "manager" }
```

**200 OK** — объект `user`.

Роль нельзя менять, пока у пользователя есть бронирование или активная аренда: иначе, например, клиент, переведённый в менеджеры, не сможет завершить начатую поездку (`start` и `finish` доступны только роли `client`). Сначала аренду нужно завершить или отменить бронирование.

**Ошибки:** `400 validation_error` (роль вне `client`, `manager`, `admin`), `403 cannot_change_own_role`, `404 not_found`, `409 user_has_active_rental` (у пользователя есть `booked` или `active` аренда).

### `PATCH /api/users/{id}`

Аналог обращения в поддержку: администратор вносит новые данные после проверки документов вне системы. Передаются только изменяемые поля (любое подмножество).

**Запрос**
```json
{ "full_name": "Петрова Анна Викторовна", "driver_license": "7708 998877" }
```

Допустимые поля: `full_name`, `driver_license`, `email`.

**200 OK** — объект `user`.

Изменение роли или данных и бронирование машины этим пользователем выполняются по очереди (блокировка строки `users`), поэтому проверка «нет открытой аренды» не может устареть.

**Ошибки:** `400 validation_error`, `404 not_found`, `409 email_taken`, `409 license_taken`, `409 user_has_active_rental` (у пользователя есть `booked` или `active` аренда).

### `DELETE /api/users/{id}`

**204 No Content.**

**Ошибки:** `403 cannot_delete_self`, `404 not_found`, `409 has_related_records`: «Нельзя удалить пользователя: у него есть аренды или записи обслуживания».

## 11. Статистика

### `GET /api/stats`

Доступ: М, А.

**200 OK**
```json
{
  "users_total": 9,
  "users_by_role": { "client": 6, "manager": 2, "admin": 1 },
  "cars_by_status": {
    "available": 12, "booked": 2, "in_use": 2, "maintenance": 1, "decommissioned": 1
  },
  "rentals_by_status": { "booked": 2, "active": 2, "completed": 8, "cancelled": 2 },
  "avg_wait_minutes": 8.8,
  "revenue_by_tariff": [
    { "tariff": "Бизнес", "rentals_count": 3, "revenue": 3199.90 },
    { "tariff": "Эконом", "rentals_count": 4, "revenue": 1763.90 },
    { "tariff": "Комфорт", "rentals_count": 3, "revenue": 1142.70 }
  ]
}
```

- `avg_wait_minutes` — среднее время от `booked_at` до `started_at` по арендам, где поездка началась (`null`, если таких аренд нет).
- `revenue_by_tariff` — выручка от завершённых поездок и платных отмен бронирований (списанное ожидание, `total_cost > 0`); `rentals_count` — число таких аренд. Группировка по тарифу, сохранённому в аренде; тарифы без выручки выводятся с нулём; порядок — по убыванию выручки.
- В `users_by_role`, `cars_by_status` и `rentals_by_status` присутствуют все значения, в том числе с нулём.
- Все показатели считаются в одной транзакции (`REPEATABLE READ`), поэтому согласованы между собой.
- Значения для примера соответствуют тестовым данным `db/seed.sql`.

## 12. Правила валидации полей

Проверка выполняется в сервисе до обращения к БД. Ограничения БД (`CHECK`, `UNIQUE`) остаются второй линией защиты.

| Поле | Правило |
|---|---|
| `email` | непустой, формат адреса, до 100 символов; уникален без учёта регистра |
| `password` | от 8 до 72 символов (ограничение bcrypt) |
| `full_name` | от 2 до 100 символов |
| `driver_license` | 10 цифр, допускается пробел после четвёртой; хранится как `NNNN NNNNNN`; уникально |
| `role` | `client`, `manager`, `admin` |
| `brand_model` | от 1 до 100 символов |
| `plate_number` | от 1 до 15 символов; уникален. Хранится без пробелов в верхнем регистре, латинские буквы-двойники (A, B, E, K, M, H, O, P, C, T, Y, X) заменяются кириллицей, поэтому `a 101 aa 777` и `А101АА777` — один номер. Поиск `q` по номеру учитывает то же правило |
| `fuel_level` | целое от 0 до 100 |
| `latitude` | число от −90 до 90 |
| `longitude` | число от −180 до 180 |
| `status` автомобиля | `available`, `booked`, `in_use`, `maintenance`, `decommissioned` (вручную — только по таблице 2.2) |
| `name` тарифа | от 1 до 50 символов; уникально без учёта регистра («Эконом» и «эконом» — одно название) |
| `price_per_min`, `waiting_per_min` | число от 0 до 999999.99, не более двух знаков после запятой |
| `description` | от 1 до 255 символов |
| `cost` | число от 0 до 99999999.99, не более двух знаков после запятой |
| `car_id`, `tariff_id`, `user_id` | положительное целое, объект должен существовать |
| `sort`, `order` | только значения из белого списка эндпоинта |
